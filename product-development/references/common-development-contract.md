# 通用开发契约

本文件只定义 React、Vue 2、Vue 3 共用的交付约束。框架 API、目录和组件写法由所选 profile 决定。

## 设计承接

- 代码必须引用当前模块详细设计覆盖的 AC、API 契约、字段规格和状态枚举。
- 不为迁就模板修改业务字段；契约有冲突时回到模块设计确认。
- 页面、弹窗、异常路径和权限拒绝均需落实，不能只实现正常列表展示。

## 数据与状态

- 对外 API 使用 `camelCase`，数据库使用 `snake_case`；转换只在后端序列化层发生。
- 枚举由后端或项目既有字典服务提供，生产模板不得内置模拟枚举或演示数据。
- 请求必须具备 loading、空态、失败态和取消/重复提交保护。
- 保存、删除、批量操作须等待真实请求成功后再更新界面；失败时保留输入并显示可操作的错误信息。

## 页面与组件

- 开发前从 `page-patterns/README.md` 选择适用模式；一个页面可组合多个模式，未命中的模式无需加载。
- 页面组件承接业务编排；布局、表格、分页、弹窗等优先复用项目现有组件。
- 页面级操作与行级操作分层；危险操作二次确认；无权限操作按产品设计隐藏或禁用。
- 列表查询、分页、排序和导出使用同一份筛选状态，避免界面结果与导出条件不一致。
- 路由、面包屑和标签状态由路由单一驱动，不维护第二份互相漂移的导航状态。

## 验证

- 运行目标项目已有的类型检查、lint、单元/组件测试、构建和 Playwright；不为换框架而跳过既有检查。
- 测试映射到 AC，并验证用户界面、API 响应和必要的数据落库结果。
- 演示数据只能存在于明确隔离的 demo/fixture 中，不得被生产模板默认导入。
- 交付前记录实际执行命令和结果；“模板看起来正确”不算验证通过。
