# 列表、批量处理与动态列

## `standard-list` 标准列表

**适用**：对象检索、分页浏览及行级增删改查。

**必备契约**

- 查询模型统一包含筛选、排序、页码和每页数量；刷新、导出和 URL 回放使用同一份有效查询。
- 区分首次加载、条件刷新、空结果和请求失败；失败后保留查询条件并提供重试。
- 新增/编辑提交期间禁止重复提交；成功后按服务端返回结果刷新，失败时保留草稿。
- 删除前显示对象标识并二次确认；删除失败后不得先从界面永久移除。

**验证**：筛选组合、分页边界、空态、请求失败、重复提交、保存失败保留输入、删除权限拒绝。

## `batch-processing` 批量处理

**适用**：批量删除、启停、分配、审批或其他多对象操作。

**必备契约**

- 明确选择范围是“当前页”“当前筛选结果”还是手工 ID 集合；跨页选择必须可见且可清空。
- 操作前展示数量、不可处理数量和不可逆影响；服务端重新校验权限与对象状态。
- API 返回每个对象的结果，至少包含对象标识、成功与否和失败原因；界面分别展示成功与失败。
- 执行期间锁定本次选择快照；完成后刷新数据，并保留失败项供重试。

**验证**：零选择禁用、跨页选择、混合权限、部分成功、重复请求幂等、执行中离开页面。

## `dynamic-columns` 动态列

**适用**：用户可控制列显隐、顺序、固定位置或宽度。

**必备契约**

- 列使用稳定 `columnId`，显示名称不能作为持久化键；权限变化或版本升级后丢弃无效列 ID。
- 必须列、操作列和主标识列不可被全部隐藏；恢复默认值使用当前版本默认配置。
- 个人配置与组织配置明确优先级；保存失败时回滚或提示未保存状态。
- 表格、导出字段和打印字段是否同步必须由产品设计明确，不能默认推断。

**验证**：隐藏/排序/固定、刷新后恢复、旧配置迁移、无权列不可通过本地配置重新显示、保存失败。
